**交叉验证（Cross-Validation, CV）** 是指把数据**多次切分**、轮流让不同的一份数据充当验证集，从而**更稳健地评估模型、挑选模型与调超参数**。在时间序列里，切分必须**严格按时间顺序**，绝不能随机打乱。

## 直观理解

假设你只做一次「训练 / 测试」切分：80% 训练、20% 测试，算出一个分数。问题是——**这个分数有运气成分**。

如果那 20% 恰好"简单"，分数就偏高；如果恰好"难"，分数就偏低。换一次随机种子，分数可能从 0.90 跳到 0.83。你拿着这种**抖动很大**的单次分数去比较两个模型、或者去调一个超参数，很可能选错——因为你看到的差异也许只是噪声。

**交叉验证的核心思想**：与其只切一次、看一次运气，不如**切很多次，让每一份数据都当过一次验证集**，然后把多次分数**平均**起来。平均之后，运气被摊薄了，得到的估计更稳、更可信。

可以打个比方：判断一个学生水平，只考一次试容易失真；考五次、取平均，才更接近真实水平。

## K 折交叉验证（k-fold）

最常用的做法是 **K 折交叉验证**，步骤如下：

1. 把数据随机（注意：时间序列**不能**随机，见后文）平均分成 $k$ 份，每一份叫一个**折（fold）**。常见取 $k=5$ 或 $k=10$。
2. 第 1 轮：用第 1 折当验证集，其余 $k-1$ 折当训练集，训练并打分，得到 $\text{score}_1$。
3. 第 2 轮：用第 2 折当验证集，其余当训练集，得到 $\text{score}_2$。
4. ……一直轮到第 $k$ 折，得到 $\text{score}_k$。
5. 把 $k$ 个分数**平均**，作为模型的交叉验证分数：

$$\text{CV score} = \frac{1}{k}\sum_{i=1}^{k}\text{score}_i$$

这样每一条样本都**恰好当过一次验证数据**，也都参与过训练，数据利用率高，估计也更稳定。除了平均值，我们还会看 $k$ 个分数的**标准差**——它告诉你模型表现到底稳不稳定。

**LOOCV（留一交叉验证）** 是 K 折的极端情形：令 $k=n$（样本总数），每次只留 **1 条**样本做验证，其余全部训练。它几乎用尽了所有数据来训练，估计偏差小，但要训练 $n$ 次、计算量极大，且方差较高，因此通常只在小数据集上使用。

## CV 是用来选模型 / 调超参，不是最终成绩

这是初学者最容易混淆的一点：**交叉验证是用于"模型选择"和"超参数调优"的工具，而不是给出最终无偏成绩的工具。**

为什么？因为当你用 CV 分数去**反复挑选**最好的超参数时，你其实是在"迎合"这些验证折——挑出的最优配置，对验证数据多少有点"[过拟合](../overfitting/)"。所以 CV 分数会**略微偏乐观**。

正确的流程是把数据分成三块：

- **训练集**：用来拟合模型参数。
- **验证集（由 CV 在训练数据内部轮换产生）**：用来调超参、选模型。
- **测试集（单独留出、全程不碰）**：只在最后跑**一次**，作为对真实泛化能力的无偏估计。

一句话：**CV 帮你"选"，留出的测试集帮你"报告成绩"**。这也是 [训练流程](../training-pipeline/) 中划分数据的关键原则，直接关系到模型的 [泛化](../generalization/) 能力评估是否可信。

## 一个具体例子

普通（非时间序列）数据，用 sklearn 的 `cross_val_score` 一行搞定：

```python
from sklearn.model_selection import cross_val_score
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier()
scores = cross_val_score(model, X, y, cv=5, scoring="accuracy")
print(scores)            # 5 个分数，例如 [0.91 0.88 0.90 0.87 0.92]
print(scores.mean())     # 平均：0.896  ← 这就是 CV score
print(scores.std())      # 标准差：越小越稳
```

而**时间序列**必须改用 `TimeSeriesSplit`，它保证训练集永远在验证集之前：

```python
from sklearn.model_selection import TimeSeriesSplit, cross_val_score

tscv = TimeSeriesSplit(n_splits=5)          # 前向、按时间顺序切分
scores = cross_val_score(model, X, y, cv=tscv, scoring="neg_mean_absolute_error")
print(-scores.mean())                        # 平均 MAE
```

注意：`TimeSeriesSplit` 切出的折**不是大小相等、互不重叠**的随机块，而是"训练集越来越长、验证集始终在未来"的滚动结构。

## 在时间序列预测中的意义

这是本节**最关键**的部分。时间序列数据有"时间方向"，未来不能用来预测过去，因此交叉验证必须特殊处理。

**为什么普通 K 折会出错？** 普通 K 折会先把数据**打乱**再分折。这意味着某一折的训练集里，可能混进了**比验证样本更晚发生**的数据。模型相当于"偷看了未来"再去预测过去，这叫 **未来泄漏（look-ahead leakage / data leakage）**。结果是：交叉验证分数**虚高**得离谱，可一旦上线、真正面对未知的未来，模型立刻翻车。

**正确做法：滚动 / 前向验证（walk-forward / rolling-origin）。** 始终让 **训练集的时间 < 验证集的时间**。把时间轴从早到晚切成若干段，逐步往后推：

```
第1轮  训练[1..100]            验证[101..120]
第2轮  训练[1..120]            验证[121..140]
第3轮  训练[1..140]            验证[141..160]
...
```

这就是 `TimeSeriesSplit` 的逻辑：每一轮都模拟"站在某个时间点，用过去预测未来"的真实场景。

**扩展窗口 vs 滑动窗口**，两种常见变体：

- **扩展窗口（expanding window）**：训练集不断**变长**，把所有历史都纳入（如上图）。适合数据规律稳定、希望尽量多用历史的场景。
- **滑动窗口（sliding window）**：训练集**长度固定**，整体随时间一起向前平移（丢掉最旧的、加入最新的）。适合数据规律会**漂移**、近期数据更有代表性的场景。

**gap / embargo（间隔 / 隔离带）**：当特征里含有滑动均值、滞后项等"跨多步"的信息时，训练集末尾和验证集开头可能**在时间上重叠**而造成泄漏。解决办法是在训练集和验证集之间**空出一小段**（gap / embargo），不让相邻样本互相"渗透"。

## 常见误区

- **对时间序列做随机打乱的 K 折**：直接造成未来泄漏，分数虚高、上线即崩。时间序列永远按时间顺序切。
- **特征缩放在全量数据上 `fit`**：在划分前就用全体数据算均值 / 标准差（或做归一化），等于把验证集 / 测试集的信息泄漏给了训练。正确做法是**只在训练折上 `fit`**，再 `transform` 验证折——放进 `Pipeline` 里随 CV 自动处理。
- **拿测试集来调超参**：测试集一旦被"看过"、被用来选参数，就不再无偏了，成绩会过分乐观。测试集只在最最后用一次。
- **忽略各折分数的方差**：只看平均、不看标准差，可能掩盖了模型在某些时间段极不稳定的事实。

## 小结

- 交叉验证 = 多次切分、轮流验证、取平均，得到比单次切分**更稳健**的评估。
- K 折：分成 $k$ 份，轮流留一份验证，分数取平均 $\frac1k\sum_i\text{score}_i$；LOOCV 是 $k=n$ 的极端版。
- CV 用于**选模型 / 调超参**；最终无偏成绩要靠**单独留出的测试集**。
- 时间序列**绝不能随机打乱**——必须用 `TimeSeriesSplit` 这类**前向 / 滚动**验证，并保证训练时间 < 验证时间，必要时加 gap/embargo。
