> 出自[数学基础](../math/) · [基础课总览](../)

交叉熵衡量"**用模型预测的分布去描述真实分布**"时的平均代价。它是分类任务最常用的[损失函数](../loss-function/)——模型越接近真相，交叉熵越小。

## 直观理解

[熵](../entropy/)度量的是"对真实情况进行最优编码所需的平均比特数"。交叉熵则问一个更现实的问题：**如果我用一套"错误的"编码（基于模型的预测 $q$）去描述真实发生的事件（真实分布 $p$），平均要花多少比特？**

只要预测 $q$ 偏离真相 $p$，你就会用上更长的编码，付出额外代价。预测越准，这个代价越接近熵的下限；预测越离谱，代价越高。所以"最小化交叉熵"等价于"让预测分布尽量贴近真实分布"。

## 数学表达

离散分布下，真实分布 $p$ 与预测分布 $q$ 的交叉熵：

$$
H(p,q)=-\sum_i p_i \log q_i
$$

- $p_i$ —— 类别 $i$ 的真实概率（分类中常是 one-hot：正确类为 1，其余为 0）；
- $q_i$ —— 模型预测类别 $i$ 的概率；
- $\log$ 取 2 为底单位是比特，取 $e$ 为底（机器学习常用）单位是 nat。

它与[熵](../entropy/)、[KL 散度](../kl-divergence/)的关系是：

$$
H(p,q)=H(p)+D_{\mathrm{KL}}(p\parallel q)
$$

由于 $H(p)$（真实分布的熵）是常数，**最小化交叉熵 = 最小化 KL 散度 = 让 $q$ 逼近 $p$**。

当 $p$ 是 one-hot（设正确类为 $c$）时公式塌缩为简洁的形式：

$$
H(p,q)=-\log q_c
$$

即"**负对数似然**"——只惩罚你给正确答案分配的概率太低。

## 一个具体例子

三分类，真实标签是第 1 类，one-hot $p=[1,0,0]$。

- 模型 A 预测 $q=[0.7,0.2,0.1]$：损失 $=-\log 0.7\approx 0.357$。
- 模型 B 预测 $q=[0.3,0.4,0.3]$：损失 $=-\log 0.3\approx 1.204$。

模型 A 给正确类更高概率，交叉熵更小，这正是我们想要的。

```python
import numpy as np
def cross_entropy(p, q):
    q = np.clip(q, 1e-12, 1.0)        # 防止 log(0)
    return -np.sum(p * np.log(q))
p = np.array([1, 0, 0])
print(round(cross_entropy(p, [0.7, 0.2, 0.1]), 3))  # 0.357
print(round(cross_entropy(p, [0.3, 0.4, 0.3]), 3))  # 1.204
```

## 为什么重要 / 用在哪

- **分类的默认损失**：图像分类、语言模型下一个词预测，几乎都用交叉熵（配合 softmax 输出概率）。
- **梯度漂亮**：softmax + 交叉熵的组合，梯度恰好是 $q-p$（预测减真实），简洁又稳定，便于训练。
- 它等价于**极大似然**：最小化交叉熵就是在做[极大似然估计](../maximum-likelihood/)。

## 在时间序列预测中的意义

- 当预测被建模成**分类问题**时（如预测"涨/平/跌"，或把数值分桶离散化、概率预测），交叉熵是天然损失。
- 概率型预测模型输出未来值的分布，用交叉熵（或其连续推广）来评估"预测分布有多贴合实际发生的值"。
- 即便 KUN（Kernel U-Net）等回归任务常用 MSE，理解交叉熵也能帮助你在需要**概率输出 / 分位数预测**时选对损失。

## 常见误区

- **交叉熵不对称**：$H(p,q)\ne H(q,p)$，参数顺序不能调换。
- 记得给 $q$ 做数值裁剪（避免 $\log 0$ 变成无穷）。
- 交叉熵 $\ge$ 熵 $H(p)$，等号当且仅当 $q=p$——它永远不会比"知道真相"更省。
