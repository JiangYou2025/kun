**算法**就是解决某类问题的一套明确、有限的步骤。给定输入，按这套步骤一步步执行，最终一定能得到正确输出。它是程序的「灵魂」，[数据结构](../data-structures/)则是它操作的「身体」。

## 直观理解

想象你要在一本厚厚的纸质电话簿里找「张伟」这个名字。

- **笨办法**：从第一页开始，一个一个往后翻，直到找到。这叫**线性查找**，最坏情况要翻完整本书。
- **聪明办法**：翻到中间，看看「张」在前半还是后半，丢掉一半，再在剩下的一半里翻到中间……每翻一次就排除一半。这叫**二分查找**。

两种办法都能找到人，但效率天差地别。一本 100 万人的电话簿，线性查找最坏要翻 100 万次，二分查找只要约 20 次（因为 $2^{20} \approx 10^6$）。**这就是算法的力量：同一个问题，好算法能快上千万倍。**

算法关心的不只是「能不能解」，更是「用多少时间、多少内存解」。衡量这一点的尺子就是 [Big-O 复杂度](../big-o/)。

## 核心要点

一个算法通常要满足几条性质：

- **有限性**：步骤有限，一定会停下来（不能死循环）。
- **确定性**：每一步都明确无歧义。
- **有输入有输出**：吃进数据，吐出结果。
- **可行性**：每一步都能在有限时间内完成。

设计算法时，最常用的几种「套路」（范式）包括：

- **暴力枚举**：把所有可能都试一遍。简单但往往慢。
- **分治**：把大问题切成小问题，分别解决再合并（如归并排序、二分查找）。
- **贪心**：每一步都选当前看起来最优的，期望全局最优。
- **[动态规划](../dynamic-programming/)**：把问题拆成重叠的子问题，缓存中间结果避免重复计算。

## 一个例子

下面用 Python 对比线性查找和二分查找：

```python
def linear_search(arr, target):
    """从头扫到尾，最坏 O(n)"""
    for i, x in enumerate(arr):
        if x == target:
            return i
    return -1

def binary_search(arr, target):
    """要求 arr 已排序，每次砍一半，O(log n)"""
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1     # 目标在右半边
        else:
            hi = mid - 1     # 目标在左半边
    return -1

data = list(range(1_000_000))   # 已排序：0,1,2,...,999999
print(binary_search(data, 987654))   # 输出: 987654
```

`binary_search` 对百万元素只需约 20 次比较；`linear_search` 最坏要 100 万次。注意二分查找有个**前提条件**：数据必须已排序——这正体现了算法与数据结构的配合。

## 在时间序列预测中的意义

时间序列分析里到处是算法：

- **DTW（动态时间规整）** 用[动态规划](../dynamic-programming/)对齐两条快慢不同的序列。
- **FFT（快速傅里叶变换）** 把求频谱从 $O(n^2)$ 降到 $O(n\log n)$，让周期分析在长序列上可行。
- 训练 **KUN / Kernel U-Net** 这类模型时，如何高效地把长序列切成窗口、做卷积下采样，本质上都是算法与数据结构的设计问题。

当数据量从几千涨到几百万个时间点，**一个 $O(n^2)$ 的实现可能直接跑不动**，而 $O(n\log n)$ 的版本几秒钟就完成。选对算法，往往比换台更快的机器更管用。

## 小结

- 算法 = 解决问题的有限、确定步骤；好坏的尺子是[复杂度](../big-o/)。
- 同一问题可以有很多算法，效率可能差好几个数量级。
- 常见范式：暴力、分治、贪心、[动态规划](../dynamic-programming/)。
- 算法与[数据结构](../data-structures/)密不可分——选对结构，算法才能快。
