**动态规划（Dynamic Programming, DP）**是一种[算法](../algorithms/)范式：把一个大问题拆成许多**互相重叠**的小问题，把每个小问题的答案**存起来**，避免一遍遍重复计算。

## 直观理解

经典例子是斐波那契数列 $F(n) = F(n-1) + F(n-2)$。

如果直接递归，会发生什么？算 $F(5)$ 要算 $F(4)$ 和 $F(3)$；算 $F(4)$ 又要算 $F(3)$ 和 $F(2)$……**$F(3)$ 被算了好几遍**，越往下重复越严重，总耗时是指数级 $O(2^n)$。

动态规划的洞察是：**$F(3)$ 算一次记下来，下次直接查表。** 这样每个子问题只算一次，复杂度立刻降到 $O(n)$。

一个问题能用 DP，通常要满足两条：

- **重叠子问题**：同样的小问题被反复需要（否则缓存没意义）。
- **最优子结构**：大问题的最优解，能由小问题的最优解拼出来。

## 核心要点

DP 有两种等价的实现风格：

- **自顶向下 + 记忆化（memoization）**：照常递归，但把算过的结果缓存起来，下次直接返回。
- **自底向上 + 制表（tabulation）**：从最小的子问题开始，用一张表（数组）一步步填到目标。

设计 DP 的三步：

1. **定义状态**：用什么变量描述一个子问题（如「前 i 个元素的最优解」）。
2. **写出状态转移方程**：大状态怎么由小状态推出来。
3. **确定边界**：最小子问题的答案是什么。

## 一个例子

对比朴素递归和带缓存的版本：

```python
# 朴素递归：指数级 O(2^n)，n=40 就慢得离谱
def fib_slow(n):
    if n < 2:
        return n
    return fib_slow(n - 1) + fib_slow(n - 2)

# 自底向上 DP：O(n) 时间，O(1) 空间
def fib_dp(n):
    if n < 2:
        return n
    prev, cur = 0, 1
    for _ in range(2, n + 1):
        prev, cur = cur, prev + cur   # 只保留最近两个状态
    return cur

print(fib_dp(50))      # 12586269025，瞬间出结果
```

Python 还内置了一行就能记忆化的装饰器：

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
# 加上缓存后，原本指数级的递归立刻变成 O(n)
```

## 在时间序列预测中的意义

动态规划是许多经典时序算法的核心引擎：

- **DTW（动态时间规整）**：衡量两条「快慢不同步」的序列有多相似。它用一张二维 DP 表，每格 $D[i][j]$ 表示两条序列前缀对齐的最小累计距离，转移方程为：

  $$D[i][j] = d(a_i, b_j) + \min\big(D[i-1][j],\ D[i][j-1],\ D[i-1][j-1]\big)$$

- **维特比算法（Viterbi）**：在隐马尔可夫模型里找最可能的状态序列，靠 DP 在指数级的路径空间里高效求最优。
- **变点检测、最优分段**：把序列切成若干段使总误差最小，也常用 DP 求解。

这些算法面对长序列时，正因为有 DP 的「算一次、存起来」，才把指数级的暴力搜索压到了多项式时间。

## 常见误区

- **以为 DP 就是递归**：递归只是一种写法，DP 的灵魂是**缓存子问题答案**。没有重叠子问题，缓存就没用。
- **状态定义不清**：状态没定义对，转移方程必然写错。先想清楚「一个子问题用什么描述」。
- **忘了边界**：最小子问题的初值漏掉或写错，整张表就垮了。
- **空间没优化**：很多 DP 只依赖最近一两个状态（如斐波那契），可以从 $O(n)$ 空间降到 $O(1)$。
