## 12.1 Certaines données sont « différentes »

Toutes les séries ne se comportent pas sagement. Les rendements financiers, les cours boursiers, le nombre de partages sur les réseaux sociaux ou le trafic d'un site web partagent souvent quelques « tempéraments » :

- **Plusieurs ordres de grandeur** : 100 aujourd'hui, peut-être 1 million demain — les valeurs couvrent plusieurs ordres de grandeur.
- **Queue lourde / événements extrêmes** : de temps à autre, une envolée ou un effondrement bien au-delà des fluctuations habituelles.
- **Variance qui dépend du niveau** : plus la valeur est grande, plus la fluctuation absolue est forte (structure multiplicative, voir les leçons 5 et 6).

Si l'on modélise directement ce type de données, quelques valeurs extrêmes dominent tout. Cette leçon présente deux outils complémentaires : la **transformation log** pour les dompter, et le **lissage exponentiel**, une approche classique, pour prévoir rapidement.

## 12.2 La transformation log : pourquoi et comment

Pour ce type de données, la première étape la plus courante consiste à prendre le logarithme :

$$y_t = \log x_t \quad(\text{ou } \log(1+x_t)\ \text{pour admettre } x_t = 0).$$

Elle apporte trois bienfaits :

1. **Compresser les ordres de grandeur** : les valeurs qui s'étalent sur plusieurs ordres de grandeur sont ramenées à une même échelle, et les valeurs extrêmes cessent de tout écraser.
2. **Stabiliser la variance** : les « fluctuations multiplicatives » deviennent « additives » — rappelez-vous la leçon 5 : $\log(T_t S_t R_t) = \log T_t + \log S_t + \log R_t$.
3. **Linéariser les « variations relatives »** : la différence logarithmique $\log x_t - \log x_{t-1}$ approche le **rendement / taux de croissance**, précisément la quantité qui intéresse le plus la finance.

> **La pratique standard en finance** : on ne prévoit presque jamais directement le prix $x_t$, mais le **rendement logarithmique** $r_t = \log x_t - \log x_{t-1}$ — plus proche de la stationnarité, sans unité, et directement relié aux mesures de risque. Pour les données de comptage comme les tweets ou le trafic, on utilise souvent $\log(1+x)$.

## 12.3 Ne pas oublier la transformation inverse

Après avoir modélisé et prévu dans l'espace log, il faut finalement revenir à l'échelle d'origine via $\hat{x}_t = \exp(\hat{y}_t)$ pour exploiter le résultat. Attention : $\exp$ n'est pas linéaire, donc « la moyenne dans l'espace log », une fois retransformée, n'est pas égale à « la moyenne dans l'espace d'origine » ; pour obtenir une prévision ponctuelle sans biais, il faut ajouter un terme de correction de variance. La transformation de Box-Cox (leçon 6) généralise le log et s'y réduit lorsque $\lambda \to 0$.

## 12.4 Le lissage exponentiel : une autre grande lignée classique

Après les transformations, passons à une famille de modèles classiques particulièrement adaptée à ce type de données métier : le **lissage exponentiel**. Son intuition centrale : **plus une observation est récente, plus elle compte, et les poids décroissent exponentiellement dans le temps**. La forme la plus simple est le **lissage exponentiel simple (SES)** :

$$\hat{x}_{t+1} = \alpha x_t + (1-\alpha)\hat{x}_t, \qquad \alpha \in (0,1).$$

Plus $\alpha$ est grand, plus les valeurs récentes pèsent ; plus il est petit, plus le lissage est fort. En déroulant la récurrence, on voit qu'il s'agit en fait d'une moyenne pondérée exponentiellement de tout l'historique. Le SES convient aux séries **sans tendance ni saisonnalité** et équivaut à un ARIMA(0,1,1).

## 12.5 Holt et Holt-Winters : ajouter tendance et saisonnalité

- **Méthode de tendance linéaire de Holt** : on ajoute un terme de tendance au SES, avec deux équations de récurrence qui mettent à jour respectivement le niveau $\ell_t$ et la tendance $b_t$ ; la prévision est $\hat{x}_{t+h} = \ell_t + h\,b_t$.
- **Holt-Winters** : on ajoute encore un terme saisonnier $s_t$ pour obtenir le modèle complet.

$$\text{additif :}\ \hat{x}_{t+h} = \ell_t + h b_t + s_{t-m+h}, \qquad \text{multiplicatif :}\ \hat{x}_{t+h} = (\ell_t + h b_t)\times s_{t-m+h}.$$

La **version multiplicative** correspond exactement aux données dont « les fluctuations saisonnières s'amplifient avec le niveau » — c'est l'autre face de l'idée log de la section 12.2 (appliquer d'abord le log puis la version additive revient souvent au même que la version multiplicative directe).

## 12.6 Le cadre ETS

ETS = **E**rror + **T**rend + **S**easonal (erreur, tendance, saisonnalité) : il combine systématiquement les variantes additives, multiplicatives et amorties des trois composantes :

| Composante | Options |
|------|------|
| Error | A (additive) / M (multiplicative) |
| Trend | N (aucune) / A (additive) / Ad (amortie) |
| Seasonal | N (aucune) / A (additive) / M (multiplicative) |

`statsforecast` / `statsmodels` choisissent automatiquement la meilleure combinaison selon l'AIC. La **tendance amortie (damped)** utilise un $0<\phi<1$ pour aplatir progressivement la tendance avec l'horizon, ce qui évite que les extrapolations lointaines « s'envolent » ; c'est souvent un choix par défaut robuste.

## 12.7 Points pratiques

- **Transformer avant de modéliser** : pour les données financières ou de comptage, stabiliser d'abord la variance par un log (ou un Box-Cox), puis passer à ARIMA / ETS / modèles profonds.
- **Lissage exponentiel ou ARIMA** : les idées diffèrent (moyenne pondérée d'un côté, combinaison linéaire de valeurs et d'erreurs de l'autre), mais beaucoup de modèles ETS ont une forme ARIMA équivalente. En pratique, essayez les deux et gardez le meilleur.
- **Traiter à part les événements extrêmes** : le log compresse mais n'élimine pas les cygnes noirs ; dans les contextes de risque, examinez les queues avec la prévision probabiliste de la leçon 14.
