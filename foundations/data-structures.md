**数据结构**是组织和存储数据的方式。选对结构，常见操作（查找、插入、删除）就快；选错了，同样的[算法](../algorithms/)可能慢上几个数量级。

## 直观理解

数据结构就像收纳工具，每种擅长不同的事：

- **数组（list）** 像一排连号的储物柜：知道编号就能瞬间取（$O(1)$），但要在中间插一个，后面全得挪位。
- **哈希表（dict）** 像带索引的字典：报出「钥匙」立刻翻到对应「值」，平均 $O(1)$。
- **栈** 像一摞盘子：只能从顶上拿放（后进先出）。
- **队列** 像排队买票：先来的先走（先进先出）。
- **树 / 图** 像家谱或地铁线路图：表达层级与连接关系。

**没有「最好」的数据结构，只有「最适合当前操作」的数据结构。**

## 核心要点

不同结构在不同操作上的复杂度差别很大：

| 结构 | 按位置取 | 按值查找 | 插入/删除 | 典型场景 |
|---|---|---|---|---|
| 数组 list | $O(1)$ | $O(n)$ | 中间 $O(n)$ | 顺序存储、随机访问 |
| 哈希表 dict/set | — | $O(1)$ 均摊 | $O(1)$ 均摊 | 查重、计数、查表 |
| 栈/队列 | — | $O(n)$ | 端点 $O(1)$ | 撤销、广搜、缓冲 |
| 平衡树 | — | $O(\log n)$ | $O(\log n)$ | 有序集合、区间查询 |

记住一个核心权衡：**用空间换时间**。哈希表多占一些内存，换来近乎瞬时的查找。

## 一个例子

同一个任务——「统计哪些元素重复出现」——用不同结构，复杂度天差地别：

```python
# 笨办法：用 list，每个元素都和后面所有比一遍 → O(n^2)
def dups_slow(arr):
    seen, out = [], []
    for x in arr:
        if x in seen:        # "in list" 是 O(n) 的线性扫描！
            out.append(x)
        seen.append(x)
    return out

# 聪明办法：用 set，查找 O(1) → 整体 O(n)
def dups_fast(arr):
    seen, out = set(), []
    for x in arr:
        if x in seen:        # "in set" 平均 O(1)
            out.append(x)
        seen.add(x)
    return out
```

逻辑几乎一样，只是把 `list` 换成 `set`。在 100 万个元素上，`dups_fast` 几乎瞬间完成，`dups_slow` 可能要跑很久——**换个数据结构，比换台快机器更有效。**

再看一个高频技巧——用 `dict` 计数：

```python
from collections import Counter
counts = Counter(["a", "b", "a", "c", "a"])
print(counts)            # Counter({'a': 3, 'b': 1, 'c': 1})
print(counts["a"])      # 3，O(1) 取出
```

## 在时间序列预测中的意义

- **滑动窗口**：把长序列切成「过去 L 步 → 未来 H 步」的样本，背后是对数组的高效切片；用 [NumPy](../numpy/) 的 `stride_tricks` 还能零拷贝生成所有窗口。
- **缓存中间结果**：[动态规划](../dynamic-programming/)（如 DTW、维特比）依赖二维数组保存子问题答案。
- **特征查表**：把时间戳映射到节假日、星期等特征时，`dict` 让查找 $O(1)$。
- **KUN / Kernel U-Net** 的下采样、跳跃连接，本质都是在张量（多维数组）这一数据结构上做高效的索引与重排。

## 小结

- 数据结构决定操作快慢，与[算法](../algorithms/)和 [Big-O 复杂度](../big-o/)三位一体。
- 核心权衡是**空间换时间**：哈希表/缓存多花内存，换来更快查找。
- 实战口诀：**频繁查找用 `set`/`dict`，顺序访问用 `list`，数值批量运算用 [NumPy](../numpy/) 数组。**
- 把 `list` 换成 `set` 这种小改动，常能把 $O(n^2)$ 降到 $O(n)$。
