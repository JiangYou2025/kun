## 6.1 Pourquoi se soucier de la stationnarité

Imaginez que vous vouliez « prédire l'avenir à partir des régularités du passé ». Mais si ces régularités changent elles-mêmes sans cesse — la moyenne dérive, la variance augmente —, alors « ce que l'on a appris du passé » ne peut pas s'appliquer à l'avenir. La **stationnarité (stationarity)** décrit justement le fait que « les régularités ne changent pas avec le temps ». Si les modèles classiques comme ARIMA fonctionnent bien, c'est à condition que leur entrée soit stationnaire ; avant de les utiliser, il faut donc d'abord **tester** si la série est stationnaire, puis trouver un moyen de la **rendre stationnaire**.

## 6.2 Définition de la stationnarité

Intuitivement, les propriétés statistiques d'une **série stationnaire** ne changent pas avec le temps. La stationnarité faible (la version la plus utilisée en pratique) impose trois conditions :

$$\mathbb{E}[x_t] = \mu\ (\text{constante}), \qquad \text{Var}(x_t) = \sigma^2\ (\text{constante}), \qquad \text{Cov}(x_t, x_{t-k}) = \gamma(k)\ (\text{ne dépend que de } k).$$

Autrement dit : **moyenne constante, variance constante, et une autocorrélation qui ne dépend que de l'écart temporel $k$, et non de l'instant considéré**. La plupart des séries réelles ne les satisfont pas : elles ont une tendance (la moyenne bouge), une saisonnalité (l'autocorrélation varie selon l'instant), et leur variance change souvent elle aussi.

## 6.3 Comment trancher : les tests de racine unitaire

À l'œil nu, on se trompe facilement ; les tests statistiques sont plus fiables :

- **Test ADF (Augmented Dickey-Fuller)** : hypothèse nulle « il y a une racine unitaire (non stationnaire) ». **p < 0.05 → on rejette l'hypothèse nulle → stationnaire**.
- **Test KPSS** : l'hypothèse nulle est inversée, c'est « stationnaire ». Il complète l'ADF ; les examiner ensemble est plus sûr.

```python
from statsmodels.tsa.stattools import adfuller
print(adfuller(series)[1])   # p-value < 0.05 → stationnaire
```

## 6.4 La différenciation : retirer la tendance

Le moyen le plus courant de rendre une série stationnaire est la **différenciation (differencing)** — soustraire deux pas consécutifs :

$$\nabla x_t = x_t - x_{t-1}.$$

Une différenciation d'ordre 1 supprime une tendance linéaire ; pour la saisonnalité, on utilise la **différenciation saisonnière** :

$$\nabla_m x_t = x_t - x_{t-m},$$

où $m$ est la période (par exemple la période annuelle $m=12$ pour des données mensuelles). Le **d** de ARIMA(p, **d**, q) est précisément le nombre de différenciations ; en général, $d=1$ ou $2$ suffit.

## 6.5 Les transformations : stabiliser la variance

Lorsque **la variance augmente avec le niveau** (là où les valeurs sont grandes, les fluctuations le sont aussi : saisonnalité multiplicative), la différenciation ne suffit pas ; il faut d'abord appliquer une transformation :

$$\text{Logarithme :}\ y_t = \log x_t, \qquad \text{Box-Cox :}\ y_t = \frac{x_t^{\lambda} - 1}{\lambda}.$$

Elles **compriment les grandes valeurs et égalisent la variance**, transformant une structure multiplicative en structure additive. Les données « à queue lourde, couvrant plusieurs ordres de grandeur », comme en finance ou sur les réseaux sociaux, en ont particulièrement besoin — la leçon 12 approfondira ce point.

## 6.6 N'oubliez pas : normalisation et transformation inverse

- Les modèles profonds appliquent aussi souvent une **normalisation** (Z-score / Min-Max), dont les statistiques ne doivent être calculées que sur l'ensemble d'entraînement (leçon 2, pour éviter la fuite de données).
- Toutes les transformations (log / Box-Cox / différenciation / normalisation) doivent être **inversibles** : la prévision se fait dans l'espace transformé, et il faut à la fin **revenir à l'échelle d'origine par la transformation inverse** pour pouvoir l'utiliser.

## 6.7 Points pratiques

- **Pourquoi la stationnarité est indispensable** : les paramètres d'ARIMA sont supposés constants dans le temps ; si la série n'est pas stationnaire, les paramètres estimés sont « périmés ».
- **Ne différenciez pas à l'excès** : trop de différenciations introduisent une autocorrélation négative artificielle et amplifient le bruit. Regardez d'abord le graphique d'autocorrélation (leçon 7) et le test de racine unitaire ; si $d=1$ suffit, ne passez pas à $d=2$.
- **L'ordre** : en général, on transforme d'abord pour stabiliser la variance, puis on différencie pour retirer la tendance / la saisonnalité.
