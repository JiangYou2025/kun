## 13.1 Il n'y a pas de « meilleur modèle »

Les douze leçons précédentes ont rempli toute une boîte à outils : linéaire, ARIMA, ETS, LSTM, Transformer, KUN. La confusion la plus fréquente chez les débutants est : « mais alors, lequel dois-je utiliser ? » Réponse : **cela dépend de la tâche et des données, pas de la nouveauté du modèle**. Cette leçon ne présente aucun nouveau modèle ; elle vous apprend à **choisir l'outil en fonction du problème**.

## 13.2 D'abord, savoir quelle tâche on résout

Sous l'étiquette « séries temporelles » se cachent plusieurs tâches distinctes, et c'est là que le choix du modèle commence à bifurquer :

| Tâche | Objectif | Méthodes courantes |
|------|---------|---------|
| **Prévision (forecasting)** | À partir du passé, inférer plusieurs pas futurs | ARIMA / ETS / modèles profonds / KUN |
| **Détection d'anomalies** | Repérer les instants anormaux | Seuil sur les résidus de prévision, forêt d'isolement, erreur de reconstruction |
| **Classification** | Déterminer la classe d'une séquence entière | LSTM / TCN / Transformer, caractéristiques + GBDT |
| **Imputation** | Combler les instants manquants | Interpolation, modèles espace d'états, imputation profonde |

Le fil conducteur de ce cours est la **prévision**, mais avant de choisir un modèle, vérifiez le type de tâche : la détection d'anomalies et la classification ont des critères d'évaluation et des architectures différents.

## 13.3 « Tabulariser » le problème de prévision : caractéristiques + GBDT

Entre modèles classiques et apprentissage profond, il existe une voie intermédiaire très pratique : **transformer la série en tableau grâce à une fenêtre glissante, puis appliquer du gradient boosting sur arbres**.

```
[x₁ … x₅] → x₆       (les 5 pas passés servent de caractéristiques pour prévoir le suivant)
[x₂ … x₆] → x₇
```

Outre les valeurs retardées brutes, on peut construire de nombreuses caractéristiques utiles :

| Type de caractéristique | Exemples |
|---------|------|
| Valeurs retardées | $x_{t-1}, x_{t-7}, x_{t-30}$ |
| Statistiques glissantes | Moyenne sur 7 jours, écart-type sur 30 jours |
| Caractéristiques calendaires | Jour de la semaine, mois, jour férié ou non |
| Différences | $x_t - x_{t-1}$, $x_t - x_{t-7}$ |

**LightGBM / XGBoost** règnent sur ce type de tableau : pas besoin de normalisation, capture automatique des non-linéarités, entraînement rapide, et importance des caractéristiques consultable. Pour la vente au détail ou la prévision de la demande, où l'on dispose de « riches caractéristiques calendaires / promotionnelles », c'est souvent le choix au meilleur rapport coût-efficacité.

> Attention : une fois tabularisée, **il s'agit toujours d'une série temporelle** — la validation croisée doit utiliser `TimeSeriesSplit` (fenêtres qui avancent dans le temps), jamais un K-fold aléatoire, sous peine de fuite de données (leçon 2).

## 13.4 Les grandes lignes du choix

Associer les « caractéristiques des données » à une « famille de modèles » :

| Données / contraintes | Point de départ recommandé |
|------------|---------|
| Univariée, série courte, interprétabilité requise | ARIMA / ETS (leçons 8 et 12) |
| Riches caractéristiques calendaires / promotionnelles | GBDT (cette leçon) |
| Longueur moyenne, apprentissage de bout en bout | LSTM / GRU / TCN (leçon 9) |
| Séries longues, multivariées, gros volume de données | Transformer / PatchTST (leçon 10) |
| Multi-échelle, besoin de rapidité et de précision | KUN (leçon 11) |
| Finance / queue lourde / plusieurs ordres de grandeur | Transformation log d'abord, puis choix du modèle (leçon 12) |

## 13.5 Un flux de travail pragmatique

```
1. Clarifier la tâche        → prévision ? détection ? classification ? à quel horizon ?
2. Examiner les données      → longueur, nombre de variables, fréquence, queue lourde ? (leçons 2 et 4)
3. Lancer des références     → naïve / naïve saisonnière / linéaire, pour fixer le plancher (leçon 3)
4. Monter l'échelle          → ARIMA/ETS → GBDT → modèles profonds, en comparant chaque étape à la référence
5. Évaluer honnêtement       → backtest temporel, plusieurs métriques, analyse des résidus (leçon 4)
6. S'arrêter quand ça suffit → si le gain n'est pas net, n'ajoutez pas de complexité
```

## 13.6 Les règles d'or du choix

- **Du simple au complexe** : commencez toujours par une référence et un modèle linéaire ; un modèle complexe doit prouver qu'il fait mieux.
- **Adapter la complexité au volume de données** : peu de données, modèles classiques ; ce n'est qu'avec beaucoup de données que les modèles profonds donnent leur pleine mesure.
- **L'interprétabilité est une contrainte** : dans bien des contextes métier, on préfère « un ARIMA explicable » à « une boîte noire meilleure de 1 % ».
- **Compter aussi le calcul et la maintenance** : une fois en production, il faut réentraîner et surveiller la dérive ; un modèle simple est souvent plus serein.

> En une phrase : **choisir un modèle, ce n'est pas prendre le plus puissant, mais celui qui correspond le mieux à « tâche + données + contraintes ».**
