**决策树（decision tree）** 是一连串"是/否"判断（if-else 分裂）组成的模型：它把特征空间一刀一刀地切成若干块，每一块给出一个预测。它直观、好解释，更是[随机森林](../model-families/)和 [GBDT](../ensemble-gbdt/) 这些强力模型的基本积木。

## 直观理解

想象你在玩"二十个问题"猜东西：先问"它会动吗？"，再问"它比猫大吗？"……每个问题把可能性砍掉一半，问几轮就能锁定答案。决策树做的就是这件事——**用一连串简单的判断，把复杂的预测问题拆成一棵流程图（flowchart）**。

举个判断"今天适不适合户外跑步"的例子：

```
温度 > 32℃ ?
├── 是 → 不跑（太热）
└── 否 → 在下雨吗 ?
         ├── 是 → 不跑
         └── 否 → 风速 > 8m/s ?
                  ├── 是 → 不跑
                  └── 否 → 去跑！
```

- 每个**内部节点（internal node）** 是一个对某个特征的判断（如 `温度 > 32`）。
- 每条边是判断的一个结果（是 / 否）。
- 每个**叶子节点（leaf）** 给出最终预测。

整棵树就是把特征空间切成一块块"矩形区域"，落进同一块的样本共享同一个预测。这种结构和人脑的决策方式很像，所以**特别好解释**——你能一条路径地讲清楚"模型为什么这么判"。

## 原理：递归二分裂

树是怎么"长"出来的？核心是**递归二分裂（recursive binary splitting）**：

1. 看当前节点里的所有样本，遍历每个特征、每个可能的切分点。
2. 挑出能让子节点"最纯"的那一刀，把数据分成两半。
3. 对每个子节点重复这个过程，直到满足停止条件（节点足够纯，或样本太少，或达到最大深度）。

关键就在第 2 步——**怎么衡量"好"的分裂**？这要看任务类型。

**分类任务**：希望分裂后每个子节点尽量"纯"（同一类占多数）。常用两个指标。

**基尼不纯度（Gini impurity）**：随机抽一个样本、再按节点内类别比例随机猜它的类别，猜错的概率。

$$Gini = 1 - \sum_k p_k^2$$

其中 $p_k$ 是该节点里第 $k$ 类的比例。一个节点全是同一类时 $Gini=0$（最纯）；各类各半时最大。

**信息熵（entropy）** 与**信息增益（information gain）**：[熵](../entropy/)衡量节点的"混乱度"。

$$H = -\sum_k p_k \log p_k$$

分裂前的熵减去分裂后子节点的加权平均熵，就是**信息增益**。增益越大，说明这一刀让数据"变整齐"得越多，就越值得切。

无论用 Gini 还是熵，思路都一样：**选那个让子节点最纯、不确定性下降最多的切分**。

**回归任务**：叶子要输出一个数值，于是改为最小化子节点内的**方差 / 均方误差（MSE）**：

$$\text{MSE} = \frac{1}{n}\sum_{i}(y_i - \bar{y})^2$$

挑那一刀，使两个子节点的加权 MSE 之和最小——也就是让每块里的 $y$ 尽量集中在一起。

**叶子给出预测**：分类叶子输出该叶子里的**多数类**；回归叶子输出该叶子里 $y$ 的**平均值**。

## 过拟合与控制

决策树有个危险的本事：只要让它一直长，它能把训练集背得**一字不差**——每个样本独占一个叶子，训练误差为 0，但这是典型的[过拟合](../overfitting/)，换新数据就崩。一棵太深的树记住的是噪声，不是规律。

控制办法（都属于[正则化](../regularization/)思想，用一点偏差换方差下降）：

- **剪枝（pruning）**：先把树长大，再把对验证集没帮助的枝叶剪掉。
- **`max_depth`**：限制最大深度，不让树问太多轮问题。
- **`min_samples_leaf` / `min_samples_split`**：要求每个叶子（或每次分裂）至少有若干样本，防止为个别样本单独开一个叶子。

这些超参数都应该用[交叉验证](../cross-validation/)来选，背后正是[偏差—方差权衡](../bias-variance/)：树越深越复杂 → 偏差低、方差高；适当限制 → 找到泛化最好的甜点。

## 一个具体例子（sklearn）

```python
from sklearn.datasets import load_iris
from sklearn.tree import DecisionTreeClassifier, export_text
from sklearn.model_selection import train_test_split

X, y = load_iris(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0)

# 不加限制：容易把训练集背下来
deep = DecisionTreeClassifier(random_state=0).fit(Xtr, ytr)
print("无限制   训练:", deep.score(Xtr, ytr), " 测试:", deep.score(Xte, yte))

# 加上深度与叶子约束：更稳、更可解释
clf = DecisionTreeClassifier(max_depth=3, min_samples_leaf=5, random_state=0).fit(Xtr, ytr)
print("限制深度 训练:", clf.score(Xtr, ytr), " 测试:", clf.score(Xte, yte))

# 把整棵树以文字形式打印出来——这就是它好解释的地方
print(export_text(clf, feature_names=load_iris().feature_names))
```

你会看到：无限制的树训练分数往往是 1.0，但测试分数未必更高；而 `export_text` 打印出的规则，人人都能读懂"模型在按什么标准判断"。

## 优点与缺点

**优点**

- **可解释性强**：整棵树就是一组 if-else 规则，能直接讲给非技术人员听。
- **无需特征缩放**：分裂只看"大于/小于某个阈值"，对量纲不敏感，不必标准化。
- **天然处理混合特征**：数值、类别特征都能用；对缺失值和异常值也相对鲁棒。
- 能自动捕捉**非线性**关系和**特征之间的交互**。

**缺点**

- **高方差、不稳定**：训练数据稍微变一点，分裂点可能大变，整棵树长得完全不同。
- 单棵树容易过拟合，预测精度往往一般——这正是要用**集成**来救它的原因。

## 在时间序列预测中的意义

时间序列预测里，我们通常先把序列变成一张表格：用**滞后特征**（$t-1, t-7, \dots$）、**日历特征**（星期几、是否节假日、月份）等当输入，再喂给模型。决策树在这种表格上能做两件[线性模型](../linear-model/)做不好的事：

- 捕捉**非线性阈值**，比如"气温超过 30℃ 后用电量陡增"这种拐点。
- 捕捉**特征交互**，比如"周末 + 晴天"才会出现的高峰。

但单棵树太弱、太不稳，实战中很少单独用——它真正的价值是当 **GBDT 的基学习器**（详见[集成学习 / GBDT](../ensemble-gbdt/)）。

还有一个**至关重要的警告**：

> **树无法外推趋势（extrapolation）。**

树的预测永远是某个叶子里**训练样本的平均值**，所以它的输出**不可能超出训练时见过的取值范围**。如果一条序列长期上涨（如持续增长的销量），树面对一个比历史都高的未来值时，只会输出"它见过的最大那一档"，从而系统性地**低估趋势**。对带明显趋势的序列，常见做法是**先去趋势 / 差分，再用树类模型**建模剩下的部分。

## 小结

- **决策树**用一连串 if-else 分裂把特征空间切块，叶子给出预测；直观、好解释。
- 通过**递归二分裂**生长：分类用**基尼 $Gini=1-\sum_k p_k^2$ 或熵 $H=-\sum_k p_k\log p_k$**，回归最小化子节点**方差/MSE**。
- 叶子预测 = **多数类**（分类）或**均值**（回归）。
- 容易**过拟合**，靠**剪枝、`max_depth`、`min_samples_leaf`** 等控制（见[正则化](../regularization/)、[偏差—方差权衡](../bias-variance/)）。
- 优点：可解释、免缩放、处理混合特征；缺点：**高方差、不稳定**。
- 时序里在**滞后/日历特征**上捕捉非线性与交互；单树弱，是 [GBDT](../ensemble-gbdt/) 的基石；**无法外推趋势**，趋势序列需先去趋势/差分。同时可参考[模型族](../model-families/)了解它在模型谱系中的位置。
