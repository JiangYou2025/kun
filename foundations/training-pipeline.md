**训练流程（training pipeline）** 指的是从定义任务和损失、切分与验证数据，一直到调超参、最终评估和部署的**端到端工作流**。它不是某个算法，而是一套**做机器学习的标准"流水线 / 操作步骤"**。

## 直观理解

把训练一个模型想象成**做一道菜**：你不会上来就乱炒，而是先想清楚要做什么菜（任务），备好洗净食材（数据），按菜谱一步步来（流程），中途尝味道调咸淡（调参），最后端上桌前再确认一次味道（测试集评估）。

机器学习也一样。新手最常犯的错，就是**只盯着"选哪个模型、调哪个参数"**，却忽略了前后那一整套流程。事实上，**一个规范的流程往往比换个高级模型更能决定成败**——因为流程里藏着无数让你"自己骗自己"的陷阱（尤其是数据泄漏）。

这节课就把这条流水线一步步拆开讲。

## 标准步骤（按顺序）

**1. 明确问题与指标。** 先问清楚：要预测什么？是回归还是分类？用什么[评估指标](../evaluation-metrics/) 来定义"好"（RMSE？准确率？MAPE？）。指标要在动手前就定死，否则后面很容易"挑一个好看的指标来自夸"。

**2. 数据准备。** 包括**清洗**（处理缺失值、异常值、重复）、**特征工程**（构造有用的输入特征）、**标准化 / 归一化**（把不同量纲的特征拉到可比的尺度）。这一步通常最花时间，也最影响效果。

**3. 切分数据。** 把数据分成**训练集 / 验证集 / 测试集**三份（见下一节）。普通数据可以随机切；但**时间序列必须按时间切**——这是重中之重。

**4. 选模型 + 定义损失函数。** 挑一个[模型族](../model-families/)（[线性模型](../linear-model/)、树、神经网络……），并选好[损失函数](../loss-function/)——它定义了训练时"什么叫错"。模型和损失要和任务匹配。

**5. 训练（拟合参数）。** 在**训练集**上跑优化算法（通常是[梯度下降](../gradient-descent/)），不断调整参数让损失下降，把模型"拟合"到数据上。

**6. 验证与调超参。** **超参数**（[学习率](../learning-rate/)、树深度、正则强度 $\lambda$ 等）不能在训练集上学，得在**验证集**上挑。常用[交叉验证](../cross-validation/) 来更稳地估计性能，配合**网格搜索（grid search）** 或**随机搜索（random search）** 系统地试不同组合。

**7. 在测试集上最终评估。** 选定模型和超参后，在**从未碰过的测试集**上跑一次，得到对真实[泛化](../generalization/)能力的诚实估计。**测试集只能用一次**——多看几次它就"泄漏"了，估计就不再可信。

**8. 部署与监控。** 上线后还要持续盯着：真实世界会变（**概念漂移 / concept drift**），模型会慢慢失效，需要**定期重新训练（retraining）**。

## 三份数据集的角色

这是整个流程的骨架，务必分清：

| 数据集 | 谁来用它 | 作用 |
|---|---|---|
| **训练集（train）** | 模型参数 | **学**——梯度下降在这上面拟合参数 |
| **验证集（validation）** | 你（调参的人） | **选**——比较不同超参/模型，挑最好的 |
| **测试集（test）** | 没人，直到最后 | **考**——一次性、诚实地估计泛化能力 |

一个好记的比喻：训练集是**平时做的练习册**，验证集是**模拟考**（用来调整复习策略），测试集是**高考**（只考一次，提前看了就作弊了）。如果你反复用测试集来挑模型，它就退化成了第二个验证集，你会**[过拟合](../overfitting/)到测试集**，最终对线上表现过度乐观。

## 最大的坑：数据泄漏

**数据泄漏（data leakage）** 指的是**训练时偷偷用到了本不该看到的信息**（尤其是未来信息或测试集信息），导致离线指标好得离谱，一上线就垮。

最经典的一类：**在切分之前就做了标准化 / 特征选择**。比如你用**全部数据**算均值和方差来标准化，那么训练集就"偷看"了验证/测试集的统计信息——这就是泄漏。

正确做法是：**所有"要从数据里学东西"的预处理，都只在训练集上 fit，再 transform 到验证/测试集**。

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Ridge
from sklearn.model_selection import GridSearchCV

# 把"标准化 + 模型"打包成一条 Pipeline——
# 关键好处：在交叉验证里，scaler 只在每折的训练部分 fit，自动避免泄漏
pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("model",  Ridge()),
])

param_grid = {"model__alpha": [0.1, 1.0, 10.0]}   # 调正则强度这个超参

grid = GridSearchCV(pipe, param_grid, cv=5, scoring="neg_mean_squared_error")
grid.fit(X_train, y_train)        # 只在训练集上做交叉验证选超参

print(grid.best_params_)
# 测试集只在最后用一次：
final_score = grid.score(X_test, y_test)
```

用 `Pipeline` 的精髓在于：它保证标准化这种步骤**被"关"在每一折的训练部分里**，绝不让验证/测试数据的信息漏进来。手动对整个 `X` 做 `fit_transform` 是新手最容易犯的泄漏错误。

## 在时间序列预测中的意义

时间序列的训练流程有几条**特殊但必须遵守**的规则，因为数据有**时间顺序**，不能像普通数据那样随机打乱。

- **必须按时间顺序切分。** 训练集在前、测试集在后（比如用前 80% 的时间训练，后 20% 测试）。**绝不能随机打乱**——否则就成了"用未来预测过去"，是典型的泄漏。
- **用时间序列交叉验证（walk-forward / 滚动）。** 不能用普通 K 折（会打乱时序），而要用**逐步前移**的方式：每次都"用过去训练、预测紧接着的未来"，然后窗口往前滚动。这样验证才符合真实预测场景。详见[交叉验证](../cross-validation/)。
- **特征工程要防未来泄漏。** 构造**滚动统计**（滑动均值、滑动标准差等）时，**只能用当前时刻之前的数据**。如果你算移动平均时把"未来"也算进去，模型在离线时会"作弊"，上线必翻车。
- **监控概念漂移、定期重训练。** 时间序列的规律会随时间改变（节假日、政策、市场变化），上线后要持续监控误差，发现性能下滑就用新数据**重新训练**。
- **永远和朴素基线比。** 时间序列里有个很强的对手：**朴素预测**（"明天 = 今天"，或"明天 = 上周同一天"）。你的复杂模型如果还打不过它，说明它没学到真东西。任何结果都该先和这个基线对比。

## 常见误区 / 小结

- **只想着选模型、调参，忽视整条流程**——流程里的坑往往比模型选择更致命。
- **数据泄漏**：在切分前就标准化 / 选特征，或让未来信息进入训练——用 `Pipeline` + 只在训练集 fit 来防。
- **反复使用测试集**：测试集只能用一次，多用就过拟合到它、估计变乐观，损害真实[泛化](../overfitting/)评估。
- **时间序列随机切分 / 随机打乱**：必须按时间切、用 walk-forward 验证，滚动特征只用过去。
- **不设基线**：永远先和朴素预测比，确认模型真的有价值。
- **上线即终点**：要监控**概念漂移**并定期重训练。
- 一句话：训练流程 = **明确指标 → 备数据 → 切三份 → 选模型定[损失](../loss-function/) → 训练 → 用[交叉验证](../cross-validation/)调参 → 测试集考一次 → 部署监控**，全程提防泄漏与[过拟合](../overfitting/)。
