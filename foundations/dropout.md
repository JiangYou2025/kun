**Dropout（随机失活）** 是一种[正则化](../regularization/)技巧：训练时随机地把一部分[神经元](../neuron/)的输出临时置零，强迫网络不要过度依赖某几个单元，从而减轻[过拟合](../overfitting/)、提升[泛化](../generalization/)能力。

## 直观理解

设想一个项目小组，如果总靠一两个明星成员包办，一旦他们请假，整组就瘫了。换个管理办法：每次开会随机让一部分人"今天不发言"。久而久之，每个人都得学会独立干活、互相补位，整个团队变得更稳健。

Dropout 就是对神经元这么做的。训练时**每个 [batch](../batch/) 都随机让一批神经元"缺席"**（输出变 0），剩下的神经元必须在不同的"残缺队形"下都能完成任务。这样网络学到的特征更加**冗余而鲁棒**，不会把宝全押在某条脆弱的通路上。

它还有一个漂亮的解释：每次随机失活相当于在训练一个**不同的子网络**，最终模型近似于指数级多个子网络的"集成"（ensemble），而集成通常比单个模型更不容易过拟合。

## 原理：训练时的掩码

设某一层的输出向量为 $x = (x_1, x_2, \dots, x_n)$，给定**保留概率** $p$（keep probability，例如 $p=0.8$ 表示每个单元有 80% 概率被保留）。训练时为每个单元独立采一个 0/1 掩码：

$$
m_i \sim \text{Bernoulli}(p), \qquad \tilde{x}_i = m_i \cdot x_i
$$

- $m_i$：第 $i$ 个单元的掩码，以概率 $p$ 取 1（保留）、以概率 $1-p$ 取 0（丢弃）。
- $1-p$ 称为**丢弃率**（drop rate），常用 0.2 ~ 0.5。
- $\tilde{x}_i$：失活后的输出，被丢弃的单元直接变成 0，不参与本次前向和反向。

注意：被置零的单元在这一步**不会有[梯度](../gradient/)**，所以确实是"随机训练子网络"。

## 推理时的缩放（关键细节）

测试/推理时我们**不再随机丢弃**——要用整个网络做确定性预测。但这会带来一个问题：训练时一个单元平均只有 $p$ 的概率在线，下一层接收到的期望输入是 $p\cdot x$；推理时所有单元都在线，输入会突然变成 $x$，量级放大了 $1/p$ 倍，分布对不上。

解决办法是**缩放对齐期望**。有两种等价做法：

1. **推理时缩放**：预测时把权重（或激活）乘以 $p$，让输出回到训练时的期望量级。
2. **Inverted Dropout（更常用）**：训练时就把保留下来的单元除以 $p$，推理时则**什么都不用做**：

$$
\text{训练：}\ \tilde{x}_i = \frac{m_i \cdot x_i}{p}, \qquad \text{推理：}\ \tilde{x}_i = x_i
$$

无论哪种，目标都是保证**训练与推理时的期望输出一致**。现代框架（如 PyTorch 的 `nn.Dropout`）默认用 Inverted Dropout，并且只在 `model.train()` 模式下生效、`model.eval()` 模式下自动关闭——这点务必记牢。

## 一个具体例子

设丢弃率 $1-p = 0.5$（即 $p=0.5$），某层输出 $x = [2, 4, 6, 8]$。某次训练采到掩码 $m = [1, 0, 1, 0]$，用 Inverted Dropout：

$$
\tilde{x} = \frac{[1,0,1,0]\odot[2,4,6,8]}{0.5} = \frac{[2,0,6,0]}{0.5} = [4, 0, 12, 0]
$$

保留的两个单元被放大 2 倍以补偿丢掉的一半。验证期望：$\mathbb{E}[\tilde{x}_1] = 0.5\times 4 + 0.5\times 0 = 2 = x_1$，与原值一致。推理时则直接用 $[2,4,6,8]$。对应代码：

```python
import torch, torch.nn as nn

net = nn.Sequential(
    nn.Linear(64, 128), nn.ReLU(),
    nn.Dropout(p=0.3),          # 这里 p 是“丢弃率”
    nn.Linear(128, 1),
)
net.train()   # 训练：Dropout 生效
y = net(torch.randn(16, 64))
net.eval()    # 推理：Dropout 自动关闭，无随机性
```

注意 PyTorch 里 `nn.Dropout(p=...)` 的 `p` 是**丢弃概率**，和上面公式里的保留概率 $p$ 含义相反，使用时别搞反。

## 常见误区

- **以为推理时还在随机丢神经元**：不是。推理是确定性的，Dropout 只在训练时起作用。
- **忘了切换 `eval()` 模式**：评估时若仍处于 `train()`，预测会带随机性、结果偏弱。
- **丢弃率越大越好**：过大（如 0.8）会丢掉太多信息，导致欠拟合；通常 0.2~0.5。
- **和 [BatchNorm](../batchnorm/) 无脑叠加**：两者一起用有时会互相干扰，常见做法是优先用 BN，或把 Dropout 放在 BN 之后、靠近输出的全连接层。

## 在时间序列预测中的意义

时序数据样本相关性强、容易过拟合到训练区间的噪声。Dropout（以及它的变体如循环 Dropout、时间维 Dropout）是约束模型复杂度、提升对未来数据泛化的常用手段。它常与[早停](../early-stopping/)、权重衰减等一起，构成防过拟合的[训练实践](../training-practice/)工具箱，也用于本站的多尺度模型 **Kernel U-Net（KUN）** 等结构中。
